# Prime Fast Pay

> Payout infrastructure for AI agents. Tell your agent to send the money — Prime Fast Pay picks the rail, runs the checks, and settles in seconds.

Prime Fast Pay is a single API for outbound disbursements. It routes payouts across ACH, RTP, FedNow, SEPA, SWIFT, and card networks, and exposes every endpoint to AI agents through a native MCP server.

## What it does

- Issues a payout from a typed REST request: `POST /v1/payouts`
- Screens the recipient (sanctions, PEP, velocity) before funds are reserved
- Posts to a double-entry ledger, then routes on the cheapest instant rail for that corridor
- Confirms settlement in under 30 seconds on real-time rails (RTP, FedNow, SEPA Instant)
- Replicates the entire API as typed tools through MCP for agent frameworks
- Falls back automatically if a rail degrades mid-flight
- Reconciles settlement against every rail's own reports

## Performance

- API response time: under 250ms at p95, at 5,000 req/s sustained
- Payout confirmation on real-time rails: under 30s at p95
- 9 payment rails behind a single API
- 160+ countries reachable via international wire

## AI agent integrations

The MCP server is compatible with:

- **Claude Agent SDK** — managed agent loop with MCP access built in
- **LangChain / LangGraph** — through `langchain-mcp-adapters`
- **Google ADK** — `McpToolset` drops the tools straight into a Gemini-powered agent on Vertex AI
- **CrewAI** — `MCPServerAdapter` wires payouts into any role-based crew

Install: `cargo install prime-fast-pay-mcp`
Configure: `export PRIME_FAST_PAY_API_KEY=sk_live_xxxxxxxx`

MCP tools exposed: `create_payout`, `retrieve_payout`, `list_payouts`, `cancel_payout`, `create_recipient`, `retrieve_recipient`, `list_recipients`.

## Key endpoints

- `POST /v1/payouts` — create a payout
- `GET /v1/payouts/{id}` — retrieve a payout
- `POST /v1/payouts/{id}/cancel` — cancel a payout
- `POST /v1/recipients` — create a recipient
- `GET /v1/recipients/{id}` — retrieve a recipient
- Webhooks: `payout.created`, `payout.processing`, `payout.completed`, `payout.failed`

## Security

- Segregated merchant funds, reconciled daily
- Sanctions, PEP, and fraud screening run on every instruction before funds are reserved
- Mutual TLS on every service-to-service call; no public IPs on compute
- AES-256-GCM at rest, TLS 1.3 in transit, HSM-backed ledger keys
- Active-passive multi-region deployment with quarterly failover exercises
- Scoped API keys (test keys route to sandbox, never move real money)
- Idempotent by contract — every write takes an idempotency key

## Architecture

Three layers, one payout lifecycle:

1. **Orchestration** — receives each instruction, validates it, reserves funds against the ledger, selects the best rail, tracks through confirmation
2. **Interface** — REST API, SDKs, native MCP server, dashboard, webhooks
3. **Compliance** — recipient verification, sanctions screening, velocity limits, automatic reconciliation

## FAQ

**What is Prime Fast Pay?**
Payout infrastructure for AI agents. One REST API that routes across 9 payment rails — ACH, RTP, FedNow, Push-to-Card, Virtual Card, Digital Check, SWIFT wire, SEPA SCT, SEPA Instant — plus a native MCP server so any agent framework can issue payouts as typed tool calls.

**How fast is payout settlement?**
RTP, FedNow, and SEPA Instant confirm in under 30 seconds at p95, 24/7. Push-to-Card settles in minutes. ACH settles in 1–2 business days. SWIFT wire settles same day. API p95 latency is under 250ms at 5,000 req/s sustained.

**Which payment rails are supported?**
Nine: ACH (Standard & Same-Day), RTP, FedNow, Push-to-Card, Virtual Card Issuance, Digital Check, International Wire (SWIFT), SEPA SCT, SEPA Instant. Coverage spans the US, Canada, the UK, the SEPA zone, and 160+ countries via SWIFT.

**Do you support AI agents?**
Yes. A native MCP server exposes every endpoint as a typed tool. Works with Claude Agent SDK, LangChain, Google ADK, and CrewAI. Install with `cargo install prime-fast-pay-mcp`, set your API key, and the agent has create_payout, retrieve_payout, list_payouts, cancel_payout, and recipient tools.

**Is there a free sandbox?**
Yes. Full API functionality, no card required. Sandbox keys start with `sk_test_` and never move real money. Production keys start with `sk_live_` and follow a short compliance conversation.

**How do you handle compliance?**
Sanctions, PEP, and velocity screening run on every instruction before funds are reserved — enforced by the code path, not documented in a runbook. Merchant funds are segregated and reconciled daily. Every write takes an Idempotency-Key, and every payout lifecycle is preserved as an immutable event.

**What countries are supported?**
ACH, RTP, FedNow for the United States. Push-to-Card and Virtual Card for US, CA, UK. SEPA SCT and SEPA Instant for the SEPA zone. SWIFT wire for 160+ countries. Nine rails total, all reachable through a single request shape.

**How do I get started?**
Three steps. Get an API key from the dashboard, create a recipient with bank or card details, POST to `/v1/payouts`. Sandbox keys issue in minutes. Full reference and code samples are at /docs.html.
