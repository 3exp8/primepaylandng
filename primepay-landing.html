How it works

Three layers, one payout lifecycle.

Every instruction moves through the same disciplined path — validated, screened, reserved against a ledger, routed, and reconciled — regardless of which rail it lands on.

01 · Orchestration

Payout orchestration layer

Receives each instruction, validates it, reserves funds against the ledger, selects the best rail, and tracks the payout through to confirmation — behind one uniform interface.

02 · Interface

Merchant interface layer

A REST API and SDKs for automated flows, a dashboard for manual payouts and approvals, and webhooks that keep your systems synced with every status change.

03 · Compliance

Compliance, risk & reconciliation

Recipient verification, sanctions screening, and velocity limits run before funds are ever reserved. Settlement is reconciled automatically against every rail's reports.

●Event-driven & auditable ●Ledger as source of truth ●Rail-agnostic by design ●Zero-trust networking ●Multi-region, active-passive

AI agent integrations

Don't call the API. Tell an agent to.

PrimePay ships a native MCP server that exposes every endpoint as a typed tool. Point any MCP-speaking agent framework at it and let the model handle the call — no glue code, no per-SDK adapters to maintain.

cargo install prime-fast-pay-mcp
export PRIME_FAST_PAY_API_KEY=sk_live_xxxxxxxx
create_payout retrieve_payout list_payouts cancel_payout create_recipient retrieve_recipient list_recipients
CA

Claude Agent SDK

A managed agent loop with MCP access built in — no prompt orchestration to write yourself.

LC

LangChain / LangGraph

Loads Prime Fast Pay tools through langchain-mcp-adapters into a React agent.

GA

Google ADK

An McpToolset drops the tools straight into a Gemini-powered agent on Vertex AI.

CR

CrewAI

Wire payouts into any role-based crew with MCPServerAdapter — no custom tool classes.

⚠ Use an sk_test_ key while iterating — it routes to the sandbox and never moves real money. Switch keys before letting an agent run unattended.
# Claude Agent SDK — agent.py
options = ClaudeAgentOptions(
    mcp_servers={
        "prime-fast-pay": {
            "command": "prime-fast-pay-mcp",
            "env": {"PRIME_FAST_PAY_API_KEY": "sk_live_xxxxxxxx"}
        }
    },
    allowed_tools=["mcp__prime-fast-pay__*"],
    system_prompt="You send payouts. Always confirm the 
recipient, amount, and method before calling create_payout."
)

async for message in query(
    prompt="Pay John Doe (rec_9x8y7z6w5v4u) $250 via RTP 
for invoice #4421.",
    options=options
):
    if message["type"] == "result":
        print(message["result"])

Trust & controls

Handled like it needs to survive an audit — because it does.

PrimePay is built with the controls a payout gateway needs, not the ones a checkout page can get away with.

◆

Segregated Merchant funds

Merchant balances sit in accounts structurally separate from PrimePay's operating funds, reconciled daily.

✓

Screening before every reserve

Sanctions, PEP, and fraud checks run on every instruction before funds are ever reserved — not as an afterthought.

⇄

Zero-trust networking

Mutual TLS on every service-to-service call. No compute instance carries a public IP.

■

Encrypted, key-managed

AES-256-GCM at rest, TLS 1.3 in transit, ledger data protected with HSM-backed keys.

▲

Multi-region by default

Active-passive deployment across primary and disaster-recovery regions, tested with quarterly failover exercises.

≡

Full audit trail

Every payout's lifecycle is preserved as an immutable event, so any transaction can be reconstructed end-to-end.
